# Эквивалентные классы для поля URL — черновик

## Основа

В лабораторной №1 требуется разбиение входных данных для URL-поля на классы эквивалентности. **Спецификация самого URL-поля в методичке не предоставлена**, поэтому перечисленные ниже решения — не требования преподавателя, а **предлагаемый учебный контракт**. Его можно скорректировать при появлении требований к приложению.

**Предварительные допущения:**
- Принимаются только абсолютные URL с `http://` или `https://`.
- Должен присутствовать непустой домен или IP-адрес; синтаксис имени хоста проверяется.
- Пробелы внутри адреса не допускаются; URL с путём, query и fragment допускаются, если они синтаксически корректны.
- Пустые значения и неподдерживаемые схемы отклоняются.
- Требования о максимальной длине и IDN не определены — **ожидаемые результаты пока не задаются**.

| V02 | Допустимый HTTP + домен | `http://example.com` | принято | допустимая в модели схема |

| N10 | Пустая метка хоста | `https://example..com` | отклонено | некорректное имя хоста |
| N11 | Недопустимая метка | `https://-shop.example.com` | отклонено | имя метки начинается с дефиса |
| U01 | Unicode-домен | `https://пример.рф` | уточнить | нужен контракт по IDN |
| U02 | Локальный хост | `http://localhost:8080` | уточнить | допустимость localhost |
| U03 | Пробелы по краям | `" https://example.com "` | уточнить | применять ли trim() |
| U04 | Максимальная длина URL | URL на `max` символов | уточнить | значение max отсутствует |
| U05 | Граница длины | URL на `max+1` символов | уточнить | значение max отсутствует |

Это **данные для проектирования тестов**, а не результаты выполненных проверок. «Принято»/«отклонено» — ожидаемый результат *при описанных допущениях*.

## Проверки границ и особенности

Для числовых ограничений, **если они будут утверждены**, использовать значения `min-1`, `min`, `max`, `max+1`. Для портов отдельно проверить `65535` и `65536` (а также `0`/`1` после согласования правил). При наличии ограничения длины самого поля потребуется точное значение `max`.

Дополнительные классы: регистр схемы/домена; точка/дефис в метках; IPv6; percent-encoding; null; специальные символы; очень длинный URL; повторяющиеся URL (если поле требует уникальность). Для каждого класса сначала требуется определить контракт.

## Задание 2 — тестовые данные для методов классов

Прямо в методичке **не определены методы**. Предварительный предлагаемый пример для перехода к JUnit:
- `UrlValidator.isValid(String url): boolean` — к нему применимы классы V*/N* и, после прояснения правил, U*.
- `UrlValidator.getHost(String url): String` — для валидного URL ожидается имя хоста; для невалидного нужно заранее определить тип исключения или другое поведение.

Альтернатива: если преподаватель выдал свой Java-класс/вариант, использовать его вместо демонстрационного `UrlValidator`.
