# Лабораторная работа №1 — классы эквивалентности

**Оригинальный документ:** `Лабораторная работа№1(1).docx`.

**Тема по методичке:** «Использование техники тестирования классы эквивалентности».

## Точные задания из методички

1. Разбить входные данные для **поля ввода URL** на классы эквивалентности.
2. Сформировать **наборы тестовых данных для тестирования методов классов**.

Вводная часть требует исследовать допустимые/недопустимые классы и значения **на границах классов**.

## Важные ограничения исходного задания

- **Нет** конкретного требования к URL-валидатору: набор протоколов, допустимость localhost/IP/IDN, правила портов, пробелов и максимальная длина не указаны.
- **Нет** названий классов, методов, их контрактов и исходного Java-проекта для задания 2.
- Таблица с `min`/`max` в документе — пример для **имени пользователя**, а не нормативы длины URL.
- Поэтому нельзя честно выдать произвольную таблицу «ожидается да/нет» за исходные требования преподавателя.

## Как связать с лабораторной №2 (JUnit 4)

Предлагается учебный класс `UrlValidator` с методами `isValid(String url)` и `getHost(String url)`. Сначала нужно зафиксировать контракт методов (или взять выданные преподавателем классы). Затем:
1. завершить матрицу тестовых данных №1;
2. реализовать методы;
3. применить те же данные к отдельным и параметризованным тестам JUnit 4 в [лабе №2](../lab_02_junit/);
4. прогнать тесты и сохранить результаты.

**Статус:** методичка идентифицирована; предварительный анализ подготовлен. Рабочий Java-код и фактический прогон пока не заявляются.
